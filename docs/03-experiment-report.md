# 实验报告：纯 NumPy / CPU / 无 autograd 的傅里叶谱混合 BERT 式掩码语言模型

> 目的：检验"用傅里叶变换这个简单系统 + 规模 + 丰富相互作用，能否涌现智能"这一命题中
> **最可操作的那一步**——把自注意力换成傅里叶谱混合，用最原始的优化手段在 CPU 上训练
> BERT 的真实目标（masked LM），它到底能不能 work，以及为什么。

**一句话结论**：能训起来，而且比注意力在原始 SGD 下**稳健得多**；但在本实验规模上它的
能力**只达到一个双向 4-gram 计数模型的水平**，离 BERT 的能力还差得远。
FNO 的通用逼近定理对这个结果**没有贡献**——起作用的是"恒等初始化 + 良态参数化"。

---

## 1. 设置

| 项目 | 值 |
|---|---|
| 语料 | Tiny Shakespeare，1,115,394 字符，字符级 |
| 词表 | 66（65 字符 + `[MASK]`） |
| 划分 | 前 95% 训练 / 后 5% 验证 |
| 任务 | BERT 式掩码语言建模，15% 掩码，80/10/10 替换策略 |
| 模型 | L=3 层, d=96, FFN=384, 4 头, T=96, batch=24 |
| 位置编码 | sin/cos（**无参数**，为了测试长度外推） |
| 其他 | pre-LN + 残差 + ReLU MLP + 输入输出 embedding 共享 |
| 优化器 | **SGD + momentum 0.9**，梯度裁剪 1.0，warmup 200，线性衰减到 5% |
| 禁用 | PyTorch/JAX/TF、autograd、GPU、Adam、dropout、weight decay |

三个 arm **除 token 混合层外完全相同**：

| arm | 混合层 | 全部参数 | **实际活跃的混合参数** |
|---|---|---|---|
| `fnet` | `y = Re(FFT(x))`，零参数 | 230,304 | **0** |
| `spectral` | `y = Re(IFFT(H ⊙ FFT(x)))` | 452,064\* | **28,224** |
| `attn` | 手写 4 头自注意力 | 342,048 | **111,744** |

\* `spectral` 的 452,064 里有 193,536 是为长度外推预分配、在 T=96 下**不参与计算**的频率行；
其活跃参数只有 258,528，比注意力**少 24%**。

## 2. 正确性验证（先证明代码是对的，再谈结论）

所有梯度手推，用中心差分校验，判据为**全局相对误差**（绝对误差 / 全体梯度 RMS）：

```
[gradcheck:spectral] checked=184  |grad|rms=1.602e-02  max_abs_err=1.883e-09  global_rel=1.18e-07
[gradcheck:fnet]     checked=152  |grad|rms=2.167e-02  max_abs_err=1.590e-09  global_rel=7.34e-08
[gradcheck:attn]     checked=280  |grad|rms=1.832e-02  max_abs_err=6.033e-10  global_rel=3.29e-08
GRADCHECK: ALL PASS
```

开发中真实踩到并修掉的两个坑（无 autograd 的代价）：

1. **FFT 伴随算子漏了因子 T**：`np.fft.fft` 不含 `1/T` 而 `ifft` 含，所以 `d/da = T·Re(IFFT(dz))`。
   漏掉后输入侧梯度缩小 T 倍，**但滤波器自身的梯度仍然是对的**，极具迷惑性。
2. **ReLU 缓存混用**：`dW2` 需要激活值，链式回传需要 0/1 掩码，二者被写成了同一个 cache。

## 3. 需要知道的参照线（否则"loss 降了"毫无意义）

| 预测器 | 交叉熵 | 准确率 |
|---|---|---|
| unigram（纯字频，零上下文） | 3.348 | 0.146 |
| bigram Markov | 2.536 | 0.271 |
| trigram Markov | 2.445 | 0.384 |
| 4-gram Markov | 2.425 | 0.466 |
| **双向 ±2 窗口（4 个上下文 token，纯计数）** | **1.200** | **0.725** |
| 双向 ±1 / ±3 / ±4 / ±6（纯计数） | 1.634 / 2.079 / 3.110 / 3.989 | 0.485 / 0.628 / 0.383 / 0.109 |

最后一行说明：计数模型在 >4 个上下文 token 后**因数据稀疏急剧退化**，
因此本语料上无法用计数法构造更大的"局部 oracle"。

## 4. 结果

### 4.1 等步数对照（3000 步，唯一公平的比较方式）

| arm | 配置 | val 交叉熵 | 准确率 | 稳定性 |
|---|---|---|---|---|
| **spectral** | lr 1.2, seed 1 | **1.398** | 0.588 | 单调下降 |
| **spectral** | lr 1.2, seed 0 | 1.486 | 0.578 | 单调下降 |
| attn | **lr 0.2** | 1.515 | 0.547 | 稳定 |
| attn | **`--wo_zero`** lr 0.8 | 1.530 | 0.552 | 稳定 |
| fnet | lr 1.2 | 2.478 | 0.313 | 单调下降但饱和高 |
| attn | lr 0.8, seed 1 | 3.031 | 0.240 | **崩溃** |
| attn | lr 0.8, seed 0 | 3.456 | 0.123 | **崩溃** |

### 4.2 长程（6000 步）

| arm | val | acc | 备注 |
|---|---|---|---|
| spectral lr1.2 | **1.2296** | **0.6348** | 到 6000 步仍在下降，未收敛 |
| fnet lr1.2 | 2.2499 | 0.3736 | 约 3000 步后基本饱和 |
| attn lr0.8 | 3.208 | 0.180 | 峰值 2.471@1000 后崩塌，5500 步被停止 |

### 4.3 注意力的失败是有信息量的：它是**双峰**的，不是"学不会"

```
attn lr0.8 验证曲线（seed 0）:
  step  500: 3.1732 / 0.166   ← 贴着 unigram
  step  750: 2.7734 / 0.231
  step 1000: 2.4710 / 0.322   ← 峰值
  step 1250: 3.2731 / 0.167   ← 崩塌
  step 2000: 3.3758 / 0.079   ← 比 unigram 基线(3.348)还差
  step 5500: 3.2080 / 0.180   ← 再未恢复
```

在 400 步短程扫描里看起来最优的 lr=0.8，放到长程会把注意力训崩（两个种子都崩）。
把输出投影**零初始化**（`--wo_zero`，让 block 开局等价于恒等）或把 lr 降到 0.2，它完全正常，
3000 步达到 1.51–1.53，与 spectral 同一水平。

**因此关键变量是初始化/条件数，不是"注意力 vs 傅里叶"的表达能力差异。**
对照之下 spectral 在 lr 0.05→1.2 全程稳定——它的滤波器初始化为 `H=1`，开局即是恒等。

### 4.4 长度外推：FNO 的"分辨率无关性"在语言上**不成立**

在 T=96 上训练，零样本换长度评估（验证损失 / 准确率）：

| 长度 | spectral | fnet |
|---|---|---|
| 96（训练长度） | **1.268 / 0.642** | 2.344 / 0.347 |
| 192 | 3.516 / 0.220 | 3.777 / 0.133 |
| 384 | 4.081 / 0.174 | 4.218 / 0.096 |
| 768 | 3.943 / 0.163 | 5.147 / 0.103 |

两者都**灾难性退化**。spectral 每一档都优于 fnet（相对优势保持），但"频谱参数化 →
天然长度外推"这个从 FNO 借来的直觉，在语言上**没有兑现**。

### 4.5 混合层到底学到了什么（诊断运行，1500 步，`runs/diag/*.weights.npz`）

`y = IFFT(H ⊙ FFT(x))` 等价于用核 `h = IFFT(H)` 做循环卷积，于是可以直接读核。

**逐频率幅度**：`mean|H|` ≈ 1.00–1.03，几乎不做幅度衰减；但单通道 `max|H|` 可达 5.8。

**逐通道恒等能量占比（lag 0 的核能量占比，96 个通道）**：

| 层 | 最小 | 中位数 | 最大 | 含义 |
|---|---|---|---|---|
| 0 | **0.039** | 0.995 | 1.000 | 有一条通道 **96% 是跨位置混合** |
| 1 | 0.719 | 0.998 | 1.000 | 混合最多 28% |
| 2 | 0.876 | 0.999 | 1.000 | 混合最多 12% |

**核的 lag 分布（通道平均）**：lag0 = 0.928，±1 = 0.053，±2 = 0.011，>8 仅 0.006。

**解读**：模型自发形成了**通道分工**——绝大多数通道是"恒等载体"，少数通道充当
"通信通道"做跨位置传递，且**有效核是局部的**（±1…±2）。
它没有用上参数化所允许的全局 all-to-all 混合；没有涌现"长程注意力"式结构。

## 5. 结论

1. **可行性：成立。** 纯 NumPy、手推梯度、SGD（无 Adam）、CPU，可以训练基于傅里叶谱混合的
   BERT 式掩码语言模型，并稳定超过所有 n-gram 参照线。
2. **稳健性：谱混合显著优于注意力。** 原始 SGD 下 spectral 在 lr 0.05–1.2 全程稳定；
   注意力是**双峰**的——短程调优出的 lr 会让它在长程崩塌，除非改初始化或降 lr。
   这是**优化/条件数**层面的优势，不是表达能力层面的。
3. **可学习性是关键，FFT 本身不是。** 冻结的 FNet 式混合（0 参数）稳定但天花板低得多
   （2.25 vs 1.23）。"无参数 FFT 替换注意力"能 work，但**学到了什么**才是分水岭。
4. **能力上限：很低。** 6000 步后 spectral（1.230 / 0.635）**仍不及**一个双向 ±2 计数模型
   （1.200 / 0.725）。本实验**没有**证明任何"智能涌现"，只证明该架构在该规模上能学到
   上下文相关的字级统计。
5. **通用逼近定理在这里没有起作用。** 定理说的是表达能力；本次成败由**初始化与条件数**
   决定（`H=1` 恒等开局、`Wo=0` 恒等开局都让训练变好）。"有定理背书"与"能训得动"是两件事。
6. **FNO 的分辨率无关性没有迁移到语言**：零样本长度外推对两个 arm 都失败。

## 6. 诚实的局限

- **规模极小**：1.1MB 语料 / 0.26–0.45M 参数 / 约 13 个 epoch。**这不是 BERT**，
  只是 BERT 的目标函数。没有 GLUE、没有微调、没有 33 亿词预训练。
- **只有 2 个种子、一个模型尺寸**；每个 arm 的 lr 只在 400 步上扫过，这对注意力**不公平**
  （其长程最优 lr 可能不同）。我用 lr 0.2 与 `wo_zero` 做了部分弥补，但没做完整的长程 lr 网格。
- **没有测 Adam。** "注意力不稳定"严格限于**原始 SGD** 这一约束；用 Adam 时注意力训练良好
  是共识。这条限制是本实验的前提（"不用现代那一套"），不是对注意力的普遍评价。
- 掩码是**独立 15%**，模型上下文含 `[MASK]` 噪声，而计数基线看的是干净上下文，
  这个不对等**略微不利于**神经网络。
- 长度外推只有 2 个 arm 有数据（注意力被提前停止，未收集）。

## 7. 复现

```bash
cd spectral_mlm_cpu
python3 spectral_bert.py --gradcheck                 # 梯度校验（必须先过）
bash run_main.sh 0 6000                              # 三臂主实验
bash run_followup.sh                                 # 稳健性对照（wo_zero / seed1 / lr0.2）
python3 aggregate.py "runs/main/*.final.json"        # 汇总表格
python3 plot.py                                      # 出图 runs/main/comparison.png
```

产物：`runs/main/`（主实验曲线、外推、cloze、对比图）、`runs/followup/`（对照）、
`runs/diag/`（含 `*.weights.npz`，可用 §4.5 的方法直接分析混合核）、
`runs/lrsweep/`（学习率扫描）、`runs/pilot/`。

## 8. 一个已知的工程缺陷

两个 `wo_zero` 运行的 tag 未包含 lr，同时写同一个 JSONL，导致该文件行交错损坏
（`runs/followup/attn_T96_d96_L3_s0_wozero.jsonl`）。它们各自的
`logs/fu_attn_wozero_lr*.log` 完整独立，报告中的 wo_zero 曲线取自日志。
修复方式：tag 里带上 lr。
